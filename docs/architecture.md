# Architecture

The project follows six deliberately separated responsibilities:

1. **Gramps integration** — registration, options, database access and report lifecycle.
2. **Extraction and normalization** — people, families, events, sources, citations, notes and media.
3. **Genealogical engine** — ancestry, descendants, generations, branches and deduplication.
4. **Editorial model** — the common book structure consumed by every renderer.
5. **LaTeX renderer** — print-oriented composition and PDF compilation.
6. **HTML renderer** — static web output and ZIP distribution.

The extraction and traversal layers now build a framework-independent JSON v0.7 model. Family sections have stable IDs and link to the in-scope partner and child occurrences; parent-child links retain the relevant occurrence IDs and the recorded relationship type for each parent. Each occurrence also carries `primary_occurrence_id` for the person’s first appearance, even when no full profile exists; it points back to its family sections and carries generation, branch, and path data for the genealogy marker. An ordered editorial structure links the cover, front matter, contents, ancestry, descent, documentary appendix and person index to family sections and occurrences. Eligible person profiles reference their published notes, portrait, events, media and family sections. One editorial family notice is created for each in-scope family, with a canonical section and links to every context section where that family appears; its published notes, events and media are referenced once even if the family has multiple appearances. The cover links to the available portraits of the reference couple. Only notes tagged `BOOK_PUBLICATION` enter these editorial references. Portrait selection currently uses the first referenced, non-excluded image in Gramps order, and uses the media description as its caption; validation against the supported Gramps version remains. Narrative composition and source entries remain to be built. Independent ancestry and descendant limits bound extraction; both default to unlimited. Handle-keyed caches avoid fetching an object more than once within a snapshot; missing optional references become structured diagnostics.

Editorial event references in profiles and family notices are ordered by Gramps' date sort value, with undated events at the end and the original association order as a stable tie-breaker. Approximate or overlapping date ranges still need the T-03 qualification before this can be treated as a fully validated chronology.

The editorial model now groups citation calls into one target per Citation handle. Calls retain their context, owning record, and field path, so several people, family notices, events, places, media references, and published notes can point to the same target without losing their individual call identities. Each entry also links to its Citation record, the Source named by that citation, that Source's repository references, and resolved, non-excluded media attached to the Citation. This is structural support for L5.3 and L5.4; compact citation numbers still need to be assigned from the resolved book order. The composed bibliography, footnotes, final page references, and calls from editorial contexts not yet represented are still to be built.

Editorial media placements are unique per Gramps media handle. Each placement retains every eligible contextual reference, including its rectangle and citation association, and exposes the description and featured flag. This separates one documentary placement from the distinct cropped derivatives that may be needed for different references. The conversion utility now reads originals and produces derivatives, but the report does not yet invoke it for the placement's references.

The media utility resolves database-relative paths through Gramps and refuses `BOOK_EXCLUDE`. Raster images are read locally, oriented from EXIF, cropped, and encoded as lossless PNG. PDF references follow the publication rule: an available citation URL takes precedence, an unlinked multipage PDF remains a reference, and an unlinked single-page PDF can be rasterized at 300 DPI. The resulting PNG carries that resolution as metadata; a pixel ceiling rejects unusually large pages instead of lowering resolution. Pillow and pypdfium2 are optional dependencies, and conversion keys include the source bytes, region, and versioned policy. The report does not yet invoke these utilities or turn their errors into structured diagnostics; packaging and deployment of the optional media dependencies also remain to be wired.

The traversal model assigns each occurrence a part, generation, family and branch roots while preserving alternative lineage paths. Unions and partners provide context without becoming new traversal roots. The HTML and LaTeX renderers do not consume this traversal model yet and remain placeholders. Notes expose their text only when tagged `BOOK_PUBLICATION`. Private flags are preserved, and the JSON privacy summary indicates when the snapshot contains private records or associations. The report does not yet show the publication warning required before exporting a finished book.

The adapter uses Gramps database getters only. It does not modify the database, filter out private records that the supplied database makes readable, or attempt to bypass access restrictions. It loads only the selected ancestry and descendant paths plus required family context, without expanding the ancestry of spouses introduced only by marriage.

Technical identifiers and metadata use English names. Reserved publication metadata uses the `BOOK_*` prefix, for example `BOOK_PUBLICATION`, `BOOK_PROFILE`, `BOOK_EXCLUDE`, and `BOOK_FEATURED`.

For Gramps 6 registration and manual add-on packaging conventions, the project consulted [`grostim/gramps-two-way-fan-chart`](https://github.com/grostim/gramps-two-way-fan-chart). It is an implementation reference only; its genealogy and rendering code are not copied into this project.
